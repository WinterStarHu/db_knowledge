# RBP加速恢复

## 可获得性

本特性面向oGRAC，适用于oGRAC 7.0.0-RC3及以上版本。

## 特性简介

RBP（Recovery Buffer Pool，恢复缓冲池）是一种面向故障恢复的页面缓存能力。启用RBP后，数据库运行期间会将恢复可能需要的部分页面和恢复窗口信息写入RBPS，并在实例或节点故障恢复时复用RBPS中的页面，减少仅依赖Redo回放重建页面的工作量。

RBPS（RBP Server）是RBP的页面缓存服务端，负责接收、保存和提供恢复阶段所需的页面。恢复过程中，数据库根据RBPS中的恢复窗口和安全检查结果决定是否使用RBP。满足使用条件时，可以缩短节点故障等场景下的恢复时间；如果RBPS不可用、恢复窗口不满足条件或安全检查未通过，数据库会自动回退到常规恢复。

## 客户价值

实例或节点发生故障后，数据库需要通过Redo回放重建页面，恢复时间会随着待回放日志量增加而延长。在恢复完成前，数据库无法正常提供服务，可能影响业务可用性。

RBP通过缓存恢复阶段可能使用的页面，减少故障恢复过程中需要回放的日志量，从而缩短恢复时间，帮助满足更短的RTO要求。同时，RBP具备安全检查和常规恢复回退机制，不会因为缓存服务不可用而影响数据库的正常恢复。

## 特性描述

数据库运行期间，将恢复可能需要的页面以及对应的恢复窗口信息异步写入RBPS。发生实例或节点故障后，数据库根据恢复点、恢复窗口和安全检查结果，判断是否可以使用RBPS中的页面加速恢复；满足条件时复用缓存页面并减少对应Redo的回放，否则执行常规恢复。

在两节点DTC部署中，数据库侧通常按照部署规划配置对端RBPS地址。RBP通信可以使用独立于业务访问的网络，生产环境建议为RBP/RBPS流量配置独立网卡或独立网络，降低恢复加速流量对业务网络的影响。

RBP相关主要参数如下：

```ini
USE_RBP=TRUE
RBP_FOR_RECOVERY=TRUE
RBP_PORT=2611
RBP_RT_ANALYSIS=TRUE
RBP_RT_PARSE_WORKERS=2
RBP_RT_PAGE_OWNER_WORKERS=4
RBP_ASSEMBLE_MAX_SCAN=300
RBP_IP=node1_rbp_ip,node0_rbp_ip
```

其中，`RBP_IP`用于配置RBPS的IPv4地址列表，最多支持8个地址，多个地址使用英文逗号分隔。地址列表不支持空项或使用分号分隔。`RBP_RT_ANALYSIS`用于控制运行期分析能力，关闭该参数时仍可使用基础RBP恢复加速路径。

## 特性增强

无。

## 特性约束

- 使用RBP前，需要在承载页面缓存的节点部署RBPS，并确保数据库节点可以访问RBPS监听端口。
- 修改RBP重启类参数或基础RTO重启类参数后，需要重启数据库实例使配置生效。
- 两节点DTC部署中，应根据实际部署关系配置每个数据库节点需要连接的RBPS地址。
- RBP是否实际参与恢复由恢复窗口和安全检查结果决定。即使数据库侧配置正确，条件不满足时也会自动回退到常规恢复。
- 当前RBP加速恢复仅适用于单节点压测，多写场景下暂不支持。
- 由于RBP需要进行网络传输，建议采用25GE及以上的网卡

## 依赖关系

- RBPS页面缓存服务端。
