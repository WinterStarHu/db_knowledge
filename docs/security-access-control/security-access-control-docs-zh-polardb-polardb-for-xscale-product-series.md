产品详情 我的收藏

PolarDB-X采用集中式和分布式一体化的云原生架构，为您提供从集中式到分布式平滑演进的数据库使用体验。兼容MySQL生态，并根据不同业务规模和发展阶段，提供两种核心产品系列：标准版和企业版。

标准版与企业版 在集中式和分布式一体化的云原生架构中，存储节点被独立出来作为集中式形态，完全兼容单机数据库形态。当业务增长到需要分布式扩展的时候，架构可原地升级成分布式形态，分布式组件无缝对接到原有的存储节点上进行扩展，不需要数据迁移，也不需要应用侧做改造。产品主售形态主要分为标准版（集中式形态）和企业版（分布式形态），详细架构如下： 对比与选型

对比维度 标准版 (集中式) 企业版 (分布式)

核心架构 单机形态，支持Paxos多副本、Lizard事务系统等分布式优化。
分布式形态，通过计算节点、数据节点、元数据服务协同工作，支持水平扩展。

兼容性 100%兼容MySQL生态。
高度兼容MySQL生态。

核心优势

性价比高，相比开源MySQL有30%~40%的性能提升。

金融级高可用，支持同城三机房容灾，RPO=0。

可平滑升级至企业版。

支持透明的水平扩展，最大可支持1024节点，PB级别的数据规模。

金融级高可用，支持同城三机房容灾，RPO=0。

拓展什么是透明分布式方案并提供列存只读实例，以支持HTAP混合负载。

主要限制

存在单机性能和容量瓶颈，最大规格为90核。

单表记录建议控制在500万～5000万，避免大表性能问题。
小规格（如CPU≤32核）场景下，分布式架构的额外开销可能导致性能略低于标准版。

选型建议

业务处于初期阶段，数据量和并发不高，但期望未来能平滑扩展。

从自建MySQL或其他云厂商RDS迁移，寻求更高的性价比和可用性。

需要满足跨机房容灾且RPO=0的金融级场景。

业务面临高并发瓶颈，如典型的电商交易场景。

单表数据量巨大，或整体存储空间已超过单机数据库上限。

替代开源分库分表方案，希望简化运维。
各系列实例类型 在选定产品系列后，您还需要了解其内部不同角色的实例，以满足业务需求。

标准版 (集中式)：由一个主实例和可选的多个只读实例构成。

企业版 (分布式)：提供更丰富的实例类型来应对不同负载。

产品系列 实例类型 说明 适用场景

标准版 (集中式) 主实例 集群中唯一的读写节点，承载业务的所有写入和主要读取请求。
所有标准版实例都必须包含一个主实例。

只读实例 与主实例物理资源隔离，通过Paxos协议同步数据。用于分担主实例的读取压力，实现读能力的线性扩展。
适用于高并发读取场景，以及需要进行数据同步、报表分析等读多写少的负载情况。

企业版 (分布式) 主实例 分布式集群的读写入口，由多个计算节点（CN）和数据节点（DN）构成，负责处理分布式事务、并行查询和数据分片。
所有企业版实例都必须包含一个主实例。

只读实例 与主实例资源隔离的分布式只读副本，支持强一致性读。用于实现读写分离，扩展高并发读取能力。
适用于少量报表分析、混合负载或高并发读取的场景。

列存只读实例 采用列式存储的特殊只读副本，数据存储在低成本的对象存储上，专为分析型查询（AP）优化。
适用于追求高性价比的报表分析、混合负载、数据归档或风控与审计等场景。
