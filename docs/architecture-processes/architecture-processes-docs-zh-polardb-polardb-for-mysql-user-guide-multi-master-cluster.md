产品详情 我的收藏

PolarDB MySQL版多主集群（Limitless）通过多个读写节点（RW）提供水平扩展的读写能力。根据数据组织和路由方式的不同，多主集群（Limitless）包含库表多主和多主集群分区表两种产品形态。

产品形态 库表多主 库表多主将不同数据库或数据对象分布到不同的RW节点。每个数据库或数据对象在同一时刻由一个RW节点提供读写服务，并可以在不迁移数据的情况下切换访问节点。该形态适合SaaS多租户、游戏分服以及已使用分库分表中间件的业务。
详情请参见什么是库表多主形态、使用说明和常见问题。
多主集群分区表 多主集群分区表根据分布键和拆分规则，自动将一张逻辑表的数据分布到多个分库和RW节点，由系统完成透明路由、分布式查询和分布式DDL。该形态适合大表水平拆分、高并发交易以及希望减少分库分表中间件依赖的业务。
详情请参见什么是多主集群分区表形态和使用说明。
如何选择

对比项 库表多主 多主集群分区表

数据分布粒度 数据库或数据对象 逻辑表的数据分片

写入模式 不同库或对象可在不同RW并发写入 同一逻辑表的不同分片可在多个RW并发写入

调度方式 指定或切换库、对象的RW访问点 系统按分布键自动路由

核心语法 POLARDB_WRITE_NODE DIST_DB、DBDISTRIBUTION

典型改造方式 保留现有库表划分，调整节点归属 为逻辑表选择分布键和拆分规则 如果业务已按库或表完成隔离，并且主要目标是将现有库表负载快速分散到更多RW节点，建议选择库表多主。如果单表数据量或访问压力已成为瓶颈，并且希望由数据库透明完成水平拆分，建议选择多主集群分区表。
通用能力 全局只读节点可以读取多个RW节点上的数据。在库表多主形态下，它用于执行跨库或跨数据对象的汇聚查询；在多主集群分区表形态下，它可以汇聚各分片的数据，用于执行跨分片查询。
